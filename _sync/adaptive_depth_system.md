# 🧠 Адаптивная система глубины мышления

## 📋 **ПРАВИЛА ВЫБОРА ГЛУБИНЫ:**

### 🚀 **FAST (по умолчанию)**
Включать если:
- ✅ Локальная правка
- ✅ Понятная причина проблемы
- ✅ Маленький дифф (< 50 строк)
- ✅ Есть тест/команда проверки
- ✅ Низкий риск

### 🔍 **DEEP (по триггерам)**
Включать только если:
- ❌ Нет ясной причины / симптом плавающий
- ❌ Меняешь архитектуру / несколько модулей
- ❌ Безопасность/данные/платёжки/авторизация
- ❌ Много неопределённости ("не знаю где копать")
- ❌ Требуется выбор из 2–3 стратегий

### 🔬 **ULTRA (редко)**
Только если:
- ❌ Деградация в метриках
- ❌ Регрессии
- ❌ Сложный баг
- ❌ Нужна серия экспериментов

## 🎯 **ШАБЛОН ЛОГИКИ SWE:**

### **A. Intake (всегда, 2–4 строки)**
```
Цель: [что делаем]
Ограничения: [в рамках чего]
Критерий успеха: [как поймем что получилось]
```

### **B. Plan (FAST: 3 шага, DEEP: 3–7 шагов)**
```
Гипотеза → Действие → Проверка
```

### **C. Execute**
```
Делаем изменения
```

### **D. Verify**
```
Запускаем ровно 1–2 самые сильные проверки
Если их нет — создаем минимальную (smoke/test/лог)
```

### **E. Report**
```
Что изменено:
Как проверено:
Что осталось/риски:
```

## 📝 **Reasoning Notes (максимум 6 буллетов):**
- Цель
- Ключевая гипотеза
- 1–2 альтернативы (если есть)
- Выбранный путь (почему)
- Проверка/доказательство
- Следующий риск/что мониторить

## 🎯 **ПРИНЦИПЫ:**
1. **"Сначала минимально доказать, потом расширять"**
2. **"Проверяй перед заявлением, реализуй перед отчётом"**
3. **"Чем выше риск — тем глубже reasoning; чем ниже риск — тем быстрее"**
